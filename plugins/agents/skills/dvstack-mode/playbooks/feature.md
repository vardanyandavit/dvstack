# Playbook: feature

1. If the repo is unfamiliar, load and follow `repo-recon`.
2. Load and follow `agent-ops-bar`: agree done, constraints, files in scope, blast-radius bar.
3. If the change crosses module boundaries or data shape is unclear, deepen with `agent-rigor` (short restatement only).
4. Route domain needs with `using-dvstack` (UI testability → frontend; e2e → testing; agent systems → harness). Load only the narrowest matching skills.
5. Implement the smallest change that meets done.
6. Load and follow `verify-loop`; run the honest check.
7. If a miss will recur, load `agent-trust-stack` and promote the fix up the ladder.
